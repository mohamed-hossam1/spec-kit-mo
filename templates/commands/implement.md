## Goal

Execute the implementation plan by processing and completing every task in `tasks.md` under strict engineering discipline.

### Key Pillars
1. **The Iron Law of TDD**: No production code shall be written without a failing seam test first demonstrating the gap.
2. **Mutation Testing Confidence**: Green tests alone prove nothing; verify test sensitivity by temporarily mutating a critical line of business logic to prove the test turns RED, then restoring it.
3. **Fast Feedback Loop**: Run typechecking (`tsc`, `mypy`, `cargo check`, etc.) and single-file targeted tests after code changes; run the full test suite only at the final polish stage.
4. **Living State & Checkpointing**: Mark completed tasks as `[X]` in `tasks.md` and update `picture.md` after each milestone.
5. **Safety Guardrails**: Strictly adhere to `.specify/memory/rules/safety-guard.md` (no destructive force/rm shell commands without explicit user confirmation) and `.specify/memory/rules/git.md` (explicit file staging, no blanket `git add .`).

### Phase 3: Task Execution under the Iron Law of TDD

Parse `FEATURE_DIR/tasks.md` and process tasks sequentially (or in parallel for independent `[P]` tasks):

1. **Task phases**: Setup, Tests, Core, Integration, Polish
2. **Task dependencies**: Sequential vs parallel execution rules
3. **Execution rules**:
   - **Phase 1: Pre-factoring (If scheduled in tasks.md)**:
     - Execute preparatory refactoring tasks (`[Pre-factor]`).
     - Run existing regression tests: Ensure the test suite remains 100% GREEN before touching any feature code.
   - **Phase 2: Foundational Data & Contracts**:
     - Apply database migrations per `data-model.md`.
     - Generate or update shared DTOs/schemas per `contracts/`.
     - Verify database connection and schema validity.
   - **Phase 3+: User Story Tracer Bullets (P1, P2, P3...)**:
     For each User Story, execute the strict TDD cycle:
     1. **The Red Stage (`[TDD-Red]`)**:
        - Write the integration/contract test exercising the primary testing seam in the specified test path.
        - **Execute the test in the terminal**: Verify that it FAILS with a meaningful error (e.g., 404, missing route, assertion failure).
        - *CRITICAL*: If the test passes before implementation, the test is invalid! Adjust the test to assert the true missing capability.
        - Mark test task as `[X]` in `tasks.md`.
     2. **The Green Stage (`[Impl]` & `[TDD-Green]`)**:
        - Write minimal production code in models, services, and seam controller/handler to satisfy the test.
        - Run typecheck (`tsc`, `mypy`, or language compiler) to verify clean types.
        - **Execute the test in the terminal**: Verify that it turns 100% GREEN.
        - Mark implementation and green tasks as `[X]` in `tasks.md`.
     3. **Mutation Testing Stage (`[Mutation]`)**:
        - Temporarily mutate a critical line of business logic (e.g. invert an if-condition or omit a state change).
        - Re-run the test: Verify that the test immediately turns RED.
        - Restore the correct code and verify the test returns to GREEN.
        - Mark mutation task as `[X]` in `tasks.md`.

### Phase 4: Fast Feedback, Guardrails & Living State Sync

During the execution loop:
1. **Targeted Testing**: Run ONLY the single test file relevant to the active user story during implementation. Do not waste minutes running thousands of unrelated tests on every edit.
2. **Safety Guard**: Strictly follow `.specify/memory/rules/safety-guard.md`. NEVER run `rm -rf`, `git reset --hard`, or destructive database drop commands without explicit user confirmation.
3. **Git Hygiene**: Strictly follow `.specify/memory/rules/git.md`. Stage files explicitly by path (`git add path/to/file.ts`). Never run blanket `git add .`.
4. **Living State Sync (`picture.md`)**:
   - At the completion of each User Story phase:
     - Update `## 2. Where We Stand` in `FEATURE_DIR/picture.md` (e.g. *"User Story 1 (P1 MVP) implemented and verified green"*).
     - Add dated milestone to `## 6. Evolution Trail`.
